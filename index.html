CI/CD en 5 minutos

Automatizar el camino que recorre el código desde el git push hasta producción.

Qué es cada letra

CI · Integración continua

Cada cambio se integra en la rama principal con frecuencia y dispara automáticamente build + tests. Detecta errores en minutos, no en semanas.

CD · Entrega continua

Cada versión que pasa CI queda lista para desplegar. El paso a producción es una decisión humana (botón de aprobación).

CD · Despliegue continuo

Igual que la entrega, pero el despliegue a producción es 100 % automático si todo está en verde.

Simulador de pipeline

Ejecuta el pipeline, inyecta un test que falla y compara entrega vs. despliegue continuo.

    Ejemplo real (GitHub Actions)

    name: ci
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22, cache: npm }
      - run: npm ci
      - run: npm run build
      - run: npm test

  deploy:
    needs: test
    if: github.ref == 'refs/heads/main'
    environment: production   # aprobación manual = entrega continua
    runs-on: ubuntu-latest
    steps:
      - run: ./scripts/deploy.sh

    Buenas prácticas

    • Pipelines rápidos (< 10 min): si tardan, nadie los espera.
    • Un build, muchos entornos: promueve el mismo artefacto de staging a producción.
    • Rollback fácil y despliegues pequeños y frecuentes.
    • Secretos en el gestor de CI, nunca en el repo.
